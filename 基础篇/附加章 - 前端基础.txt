附加章 - 前端基础

这是本书的附加章节，独立于主线（编程语言、运维、硬件），专门介绍前端开发的基础。前端负责用户直接看到和交互的部分。本章内容不会涉及复杂的框架（如 React、Vue），只涵盖最基础的 HTML 和 CSS，帮助读者理解网页的结构与样式

附加1 HTML —— 网页的骨架

1.1 什么是 HTML？

HTML（HyperText Markup Language，超文本标记语言）是构建网页的基础语言。它使用“标签”来描述网页的结构

一个最简单的 HTML 文档结构如下：

<!DOCTYPE html>
<html>
<head>
    <meta charset="UTF-8">
    <title>我的第一个网页</title>
</head>
<body>
    <h1>Hello, World!</h1>
    <p>这是一个段落。</p>
</body>
</html>

<!DOCTYPE html>: 声明这是一个html5文档
<html>: 根元素，包裹整个页面的所有内容
<head>: 存放元数据，如字符编码、标题、引用的样式等，用户看不到这部分内容
<meta charset="UTF-8">: 指定字符编码为 UTF-8，防止神秘的浏览器把它用ansi等其他格式解码，出现神秘三字武器“锟斤拷”
<title>: 浏览器标签页上显示的标题
<body>: 页面可见内容的容器

所有 HTML 标签都用尖括号 <请输入文本> 包裹，大多数标签是成对出现的：<tagname>请输入文本</tagname> 也有自闭合标签，如 <img>、<input>

1.2 常用块级标签
块级标签会在页面上占据一整行，默认从上到下排列
标题标签：<h1>到<h6> 重要性递减

<h1>一级标题</h1>
<h2>二级标题</h2>
<h3>三级标题</h3>
<h4>四级标题</h4>
<h5>五级标题</h5>
<h6>六级标题</h6>

段落标签：<p> 用于包裹一段文本，浏览器会自动在段落前后添加间距

<p>qwertyuiopasdfghjklzxcvbnm</p>
<p>请输入文本 浏览器会自动在段落之间添加间距</p>

列表标签：

无序列表 <ul> + <li>：用于不需要按顺序排列的项目（如菜单、特性列表）

<ul>
    <li>67676767</li>
    <li>69696969</li>
    <li>61616161</li>
</ul>

反过来就有有序列表：有序列表 <ol> + <li>：用于需要按顺序排列的项目（如步骤、排名）

<ol>
    <li>第一步：想玩roblox</li>
    <li>第二步：开加速器</li>
    <li>第三步：玩roblox</li>
</ol>

有序列表可设置 type 属性（如 type="A" 表示大写字母序号）和 start 属性（如 start="3" 表示从3开始编号）

分区标签：<div> 是一个无特定语义的块级容器，用于组合其他元素，常用于页面布局和样式分组
用div标签的话文本结构简洁明了又易读 而且可以往里面塞一些样式 如卡片样式

<div>
    <h2>文章标题</h2>
    <p>正文内容</p>
</div>

1.3 常用内联标签

内联标签不会换行，只占据其内容所需的宽度，多个内联标签可以在一行内并列（可读性 = 一坨，而且要想多次使用还得复制粘贴 不建议用）

超链接：<a>，用于链接到其他页面或页面内的位置，核心属性是 href（目标地址）和 target（打开方式，如 _blank 表示新窗口）

<a href="https://www.example.com">访问示例网站（可以打开，域名是IANA的）</a>
<a href="#section1">跳转到第一节</a>

图像：<img>，自闭合标签，核心属性是 src（图片地址）和 alt（替代文本，图片加载失败时显示）

<img src="photo.jpg" alt="一张风景照片 你网速不好打不开">
<img src="https://example.com/logo.png" alt="网站logo">

强调：<strong> 表示重要内容（通常加粗），<em> 表示强调内容（通常斜体）

<p><strong>请注意请注意，</strong>三年二班李子明同学，<em>你妈妈拿了两罐旺仔牛奶要给你</em></p>

换行：<br>，自闭合标签，用于换行（不开启新段落）

<p>请输入文本<br>请输入文本 x 2</p>

水平分割线：<hr>，自闭合标签，用于在页面中插入一条水平线，表示主题切换或分隔

<hr>

1.4 表格与表单

表格：使用 <table> 创建表格，<tr> 表示行，<td> 表示单元格，<th> 表示表头（加粗居中）

<table border="1">
    <tr>
        <th>姓名</th>
        <th>年龄</th>
    </tr>
    <tr>
        <td>张三</td>
        <td>25</td>
    </tr>
    <tr>
        <td>李四</td>
        <td>30</td>
    </tr>
</table>

border="1" 为表格添加边框，可用 cellpadding 和 cellspacing 调整内边距和外边距，但更推荐用 CSS 控制

<form action="/submit" method="POST">
    <label for="name">姓名：</label>
    <input type="text" id="name" name="username">
    <br>
    <label for="email">邮箱：</label>
    <input type="email" id="email" name="useremail">
    <br>
    <input type="submit" value="提交">
</form>

点提交后自动重定向到/submit目录上传表单

常用输入类型 type：

text：单行文本
email：邮箱（自带格式验证）
password：密码（输入时显示为圆点）
number：数字（自带增减按钮）
checkbox：复选框
radio：单选按钮（同一组 name 的 radio 互斥）
submit：提交按钮
button：普通按钮
textarea：多行文本（用 <textarea> 标签，非 type 属性）
label 的 for 属性与输入元素的 id 匹配，点击标签时会自动聚焦到对应输入框，提升用户体验

1.5 HTML5 新增语义化标签

HTML5 引入了一系列具有语义的标签，帮助开发者构建更可读、更易维护的页面结构：

<header>页面或区块的头部</header>

<footer>页面或区块的底部</footer>

这些标签在视觉上等价于 <div>，但它们为浏览器和搜索引擎提供了更清晰的结构信息，有利于可读性和页面可访问性

1.6 HTML 中的注释

注释不会被浏览器显示，用于记录代码的说明或标记：

<!-- 这是注释，浏览器不会显示 -->

注释可以多行书写，也可以放在行内，用于临时禁用代码或解释代码是啥意思

1.7 HTML 的嵌套规则

大多数 HTML 元素可以嵌套，但必须正确闭合。HTML 结构是一棵树.

附加2 CSS —— 网页的装饰

2.1 什么是 CSS？

CSS（Cascading Style Sheets，层叠样式表）用于控制 HTML 元素的外观，包括颜色、字体、大小、间距、对齐等. 它让内容和样式分离，便于维护和重用

2.2 三种引入方式

内联样式：直接在 HTML 标签上用 style 属性，只影响该标签本身（优先级最高，但不推荐 理由上面讲了）

<!-- 雷霆红色巨型67 -->
<p style="color: red; font-size: 100px;">67</p>

内部样式表：在 <head> 中使用 <style> 标签，适用于单个页面

<head>
    <style>
        <!-- 不加点将导致所有p标签的文本都会变蓝色 字体大小全变16px -->
        p {
            color: blue;
            font-size: 16px;
        }

        <!-- 加了点只需要下面class引用一下就会应用里面的内容 全局不会被影响 -->
        .para {
            color: blue;
            font-size: 67px;
        }
    </style>
</head>

如何引用：

<!-- 雷霆巨型蓝色67 -->
<p class="para">67</p>

外部样式表：将 CSS 写入独立的 .css 文件，在 HTML 中通过 <link> 引用，推荐用于多页面
html内引用这么写：

<head>
    <link rel="stylesheet" href="css/style.css">
    <!-- 以html文件所在目录为默认目录 -->
</head>

css内使用@import规则：

@import url("css/style.css");

2.3 CSS 基本语法

CSS 由选择器和声明块组成：

选择器 {
    属性: 值;
    属性: 值;
}

举个例子：

h1 {
    color: #333;
    font-size: 24px;
    text-align: center;
}

h1 是选择器，color、font-size 是属性，#333、24px 是值。多个声明之间用分号分隔

2.4 常用 CSS 选择器

选择器            示例        描述
元素选择器      p                  选中所有 <p> 元素
类选择器        .dick              选中 class="highlight" 的所有元素
ID 选择器       #id                选中 id="header" 的元素（id就一个 是元素的标识 class可以有很多个）
后代选择器      div p              选中 <div> 内的所有 <p> 元素
子元素选择器    ul > li            选中 <ul> 的直接子元素 <li>
伪类选择器      a:hover            鼠标悬停在某个元素时的状态
属性选择器      input[type="text"] 选中 type="text" 的 <input>
通配选择器      *                  选中所有元素（常用于重置样式）

伪类选择器

:hover → 鼠标悬停时生效，常用于按钮、链接
:active → 元素被激活（如点击）时生效
:focus → 输入框获得焦点时生效
:visited → 已访问的链接
:nth-child(n) → 选中父元素下的第 n 个子元素，支持 odd、even、2n+1 等
:first-child / :last-child → 选中第一个/最后一个子元素
:not(selector) → 排除符合选择器的元素

伪元素选择器

::before → 在元素内容前插入生成内容，常配合 content 使用
::after → 在元素内容后插入生成内容
::first-line → 选中块级元素的第一行文本
::first-letter → 选中块级元素的首字母


类选择器是最常用的，同一个类可应用于多个元素，而 ID 选择器通常用于唯一标识一个元素（如页头、页脚）

附加3 前端表单如何被后端接收

3.1 基本原理

前端表单的数据通过 HTTP 请求发送到后端服务器，后端通过路由（route）接收请求，并从请求体中提取数据。整个过程遵循“请求-响应”模型

流程图：

浏览器（前端） → 提交表单 → HTTP 请求 → 后端服务器 → 读取数据 → 处理 → 返回响应

3.2 HTML 表单的关键属性

举个例子：

<form action="/login" method="POST">
    <div class="form-group">
        <label for="username">账号</label>
        <input type="text" id="username" name="username" placeholder="请输入用户名">
    </div>

    <div class="form-group">
        <label for="password">密码</label>
        <input type="password" id="password" name="password" placeholder="请输入密码">
    </div>
</form>

label        给用户看的提示
for          用id匹配到哪个输入框
placeholder  用户不输入时看到的提示
action       指定数据发送到的后端地址（URL），如 /submit
method       指定 HTTP 方法，通常用 POST（提交数据）或 GET（查询数据）
name         每个输入控件的 name 属性对应后端接收时的字段名（key）

当用户点击提交按钮后，浏览器会将表单数据编码为键值对，并发送到 action 指定的地址

3.3 后端如何接收表单数据（完整流程）

要理解后端如何接收表单数据，首先需要理解 HTTP 请求的完整旅程

3.3.1 服务器在做什么？

当你在浏览器中提交表单时，浏览器会构造一个 HTTP 请求，通过网络发送到后端服务器。后端服务器（如 Flask 应用）持续运行，监听指定端口，等待请求到来

[浏览器] ─── HTTP 请求 ───→ [服务器]
                              ↓
                         监听到请求
                              ↓
                        Flask 接收请求
                              ↓
                        匹配路由（URL）
                              ↓
                        执行对应的函数

这个过程类似一个餐厅：

服务员flask在门口（端口）等着
客人（浏览器）来了，把菜单（表单数据）递给他
服务员把菜单交给后厨（处理函数），后厨做好菜（返回响应），服务员把菜端回给客人
3.3.2 HTTP 请求的组成

一个完整的 HTTP 请求包含以下部分：

部分	作用
请求行	包含请求方法（GET/POST）和 URL（路径）
请求头	包含元数据（如 Content-Type、Host）
请求体	包含实际数据（如表单字段、JSON）
当一个表单使用 method="POST" 提交时：

请求行：POST /login HTTP/1.1
请求头：Content-Type: application/x-www-form-urlencoded
请求体：username=alice&password=123456
浏览器生成的请求体原始格式（以登录表单为例）：

text
username=alice&password=123456&remember=on
这是默认的编码格式，字段名和值用 = 连接，字段之间用 & 分隔。浏览器在发送前会自动进行 URL 编码（空格变成 +，特殊字符变成 %XX）。

3.3.3 后端如何处理这个请求？

后端框架（如 Flask）会：

解析请求行：识别出 POST /login
匹配路由：找到绑定了 @app.route('/login', methods=['POST']) 的函数
解析请求头：确认数据格式（Content-Type: application/x-www-form-urlencoded）
解析请求体：把 username=alice&password=123456 转换成一个字典（Python 中的 dict 对象）
调用对应的函数，并把解析好的数据传递给函数（通过 request 对象）
代码中的 request.form 就是这个解析好的字典：

# python
@app.route('/login', methods=['POST'])
def login():
    # request 是 Flask 自动解析好的请求对象
    # request.form 是字典，包含所有表单字段
    username = request.form.get('username')  # 取出 username 字段的值
    password = request.form.get('password')  # 取出 password 字段的值
    print(f"收到登录请求：用户名={username}")
    return f"欢迎回来, {username}!"
request.form 中的数据是如何解析出来的：

Flask 读取请求体原始数据：username=alice&password=123456
按 & 分割：['username=alice', 'password=123456']
按 = 分割成键值对：{'username': 'alice', 'password': '123456'}
存入 request.form 字典中
这样，request.form.get('username') 就能取出 'alice'。

3.3.4 后端返回响应

服务器处理完请求后，需要返回一个 HTTP 响应。响应的组成：

部分	作用
状态行	HTTP 状态码（如 200、404、500）
响应头	元数据（如 Content-Type）
响应体	实际返回的数据（HTML、JSON、纯文本）
在 Flask 中，你用 return 返回的内容会成为响应体：

python
return "欢迎回来, Alice!"          # 响应体为纯文本
return jsonify({"status": "ok"})   # 响应体为 JSON
return render_template("page.html") # 响应体为完整的 HTML 页面
Flask 会自动加上默认的状态码（200 OK）和响应头（Content-Type: text/html），你不需要手动指定。

3.3.5 完整示例：前端请求 → 后端接收 → 后端返回

前端 HTML

html
<form action="http://localhost:5000/login" method="POST">
    <input type="text" name="username" placeholder="用户名">
    <input type="password" name="password" placeholder="密码">
    <button type="submit">登录</button>
</form>
后端 Flask

python
from flask import Flask, request

app = Flask(__name__)

@app.route('/login', methods=['POST'])
def login():
    username = request.form.get('username')
    password = request.form.get('password')
    
    # 简单验证
    if username == 'admin' and password == '123456':
        return f"欢迎回来, {username}！登录成功"
    else:
        return "用户名或密码错误", 400  # 返回 400 状态码

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000, debug=True)
请求-响应流程

text
1. 浏览器请求：POST http://localhost:5000/login
2. 请求体：username=admin&password=123456
3. Flask 匹配路由 /login，执行 login()
4. request.form.get('username') → 'admin'
5. 验证通过，return "欢迎回来, admin！登录成功"
6. 浏览器收到响应，显示 "欢迎回来, admin！登录成功"

方法二：在代码中打印

3.3.7 关键理解

后端接收数据不是“自动发生的”，它依赖于一个正在运行的服务器进程
服务器进程必须持续监听端口，否则请求无法到达
Flask 框架负责解析 HTTP 请求，把原始数据转换成 request 对象
request.form 中的数据在函数执行时已经解析完成，你只需要读取
函数返回的内容会成为 HTTP 响应体，发送回浏览器

3.4 后端返回后，前端如何接收与处理

在上一节中，我们了解了后端如何接收前端发送的表单数据并返回响应。本节我们将补全这个闭环的最后一步：前端收到后端响应后，如何处理并显示给用户。

前端获取后端响应有两种方式：传统浏览器自动处理和JavaScript 手动处理。前者适合传统多页面应用，后者适合前后端分离的单页应用（SPA）

3.4.1 传统方式：浏览器自动渲染

当表单通过 action 提交后，浏览器会等待服务器的响应并自动处理

<!-- 表单直接提交，浏览器自动处理响应 -->
<form action="/login" method="POST">
    <input type="text" name="username">
    <input type="password" name="password">
    <button type="submit">登录</button>
</form>

流程：
用户点击“登录”按钮 → 浏览器发送请求
后端处理并返回响应（HTML 页面、纯文本、重定向）
浏览器根据响应类型自动处理：

返回 HTML 页面 → 浏览器自动渲染，用户看到新页面
返回纯文本 → 浏览器直接显示文本内容
返回重定向（302 状态码）→ 浏览器自动跳转到新地址

@app.route('/login', methods=['POST'])
def login():
    username = request.form.get('username')
    if username == 'admin':
        # 重定向到主页
        return redirect('/dashboard')
    else:
        # 返回 HTML 字符串
        return "<h1>登录失败，请重试</h1>"
优缺点：

✅ 简单易用，无需编写额外的 JavaScript 代码
❌ 页面会刷新（用户体验较差）
❌ 无法对响应进行精细处理（如部分更新页面内容）

3.4.2 现代方式：JavaScript 手动处理（fetch / AJAX）

这种方式在现代 Web 开发中更常用。前端使用 JavaScript 发送请求，并处理后端返回的数据，页面不会刷新。

<!-- 使用 JavaScript 拦截表单提交 -->
<form id="loginForm">
    <input type="text" name="username" id="username">
    <input type="password" name="password" id="password">
    <button type="submit">登录</button>
</form>

<div id="message"></div>

<script>
document.getElementById('loginForm').addEventListener('submit', async function(e) {
    e.preventDefault();  // 阻止页面刷新

    const formData = new FormData(this);
    const response = await fetch('/login', {
        method: 'POST',
        body: formData
    });

    // 根据响应类型不同，有不同的读取方式
    const contentType = response.headers.get('content-type');

    if (contentType && contentType.includes('application/json')) {
        // 如果是 JSON 数据
        const data = await response.json();
        document.getElementById('message').textContent = data.message;
    } else {
        // 如果是纯文本或 HTML
        const text = await response.text();
        document.getElementById('message').textContent = text;
    }
});
</script>
关键点：

e.preventDefault() 阻止浏览器的默认行为，让 JavaScript 接管请求
fetch() 是浏览器内置的请求方法，返回一个 Promise 对象
response.headers.get('content-type') 获取响应类型，决定如何解析
根据不同的响应类型，使用不同的方法读取响应体：

response.json() → 解析 JSON 数据
response.text() → 读取纯文本
response.blob() → 读取二进制数据（如图片）
fetch 请求默认不携带 Cookie，需要额外设置 credentials: 'include'（如涉及用户会话保持）

3.4.4 常见响应状态码（status code）

状态码	含义	前端如何处理
200	OK / 请求成功	正常解析响应体（JSON/文本/HTML）
201	Created / 创建成功	同上，常用于 POST 请求（如注册成功）
302	Found / 重定向	检查 response.redirected 或 location 头，手动跳转
400	Bad Request / 请求有误	显示提示信息，告知用户输入错误
401	Unauthorized / 未认证	跳转到登录页或提示重新登录
403	Forbidden / 无权限	提示“您没有权限访问此资源”
404	Not Found / 资源不存在	提示“请求的资源不存在”
500	Internal Server Error / 服务器错误	提示“服务器错误，请稍后重试”

// 前端统一处理状态码
const response = await fetch('/api/data');

if (response.ok) {  // status 在 200-299 之间
    const data = await response.json();
    // 处理数据
} else if (response.status === 401) {
    window.location.href = '/login';
} else if (response.status === 404) {
    document.getElementById('msg').textContent = '数据不存在';
} else if (response.status === 500) {
    document.getElementById('msg').textContent = '服务器错误，请稍后重试';
} else {
    document.getElementById('msg').textContent = `请求失败 (${response.status})`;
}

3.4.6 前端处理响应的常见陷阱

陷阱一：忘记处理非 JSON 响应

如果后端返回的是纯文本或 HTML，而前端尝试调用 response.json()，会抛出错误。

// ❌ 错误：假设所有响应都是 JSON
const data = await response.json();

// ✅ 正确：先检查 Content-Type
const contentType = response.headers.get('content-type');
if (contentType && contentType.includes('application/json')) {
    const data = await response.json();
    // 处理 JSON 数据
} else {
    const text = await response.text();
    // 处理纯文本或 HTML
}
陷阱二：fetch 默认不携带 Cookie

默认情况下，fetch 不会发送跨域 Cookie。如果后端使用 Session（会话），需要添加配置。

// ✅ 正确：允许发送 Cookie
const response = await fetch('/api/data', {
    credentials: 'include'  // 同域请求发送 Cookie
});
陷阱三：未处理网络错误

fetch 在网络错误时会抛出异常（如服务器未启动）。

try {
    const response = await fetch('/api/data');

3.5 保持登录状态 · Cookie 机制

前面我们已经学会了如何发送表单、后端如何接收、后端如何返回响应。但有一个问题还没解决：用户登录之后，再次访问页面时，服务器如何知道他是谁？

HTTP 是无状态的协议，每次请求都是独立的。没有一种机制，服务器会"记住"上一次请求是谁发的。Cookie 就是解决这个问题的关键

3.5.1 登录流程回顾（无状态版本）

用户提交账号密码
后端验证成功 → 返回 "登录成功"
用户再次访问页面 → 服务器不知道是谁，因为上一次请求已经结束了
问题：服务器不知道第二次请求和第一次请求是同一个用户。

3.5.2 加入 Cookie 后的登录流程

text
第一次请求（登录）
浏览器 ── POST /login (username=admin&password=123) ──→ 服务器
                                                       │
                                                       验证成功
                                                       │
浏览器 ←── 响应 (Set-Cookie: user_id=admin) ────────── 服务器

第二次请求（访问主页）
浏览器 ── GET /dashboard (Cookie: user_id=admin) ────→ 服务器
                                                       │
                                                       读取 Cookie
                                                       识别用户
                                                       │
浏览器 ←── 响应 (显示 Alice 的个人主页) ────────────── 服务器
关键点：

第一次登录成功后，服务器在响应中带上 Set-Cookie 头
浏览器收到后，会自动保存这个 Cookie
之后每次访问该网站，浏览器会自动在请求头中带上这个 Cookie
服务器通过读取 Cookie，识别出用户身份
3.5.3 后端生成并返回 Cookie

Python Flask 示例

python
from flask import Flask, request, make_response, jsonify

app = Flask(__name__)

@app.route('/login', methods=['POST'])
def login():
    username = request.form.get('username')
    password = request.form.get('password')

    if username == 'admin' and password == '123456':
        # 方法一：直接通过 `make_response` 设置 Cookie
        resp = make_response(jsonify({
            "status": "success",
            "message": "登录成功"
        }))
        # 设置 Cookie（key, value, 过期时间, 路径）
        resp.set_cookie('user_id', username, max_age=3600, path='/')
        # max_age=3600 表示 1 小时后过期（单位：秒）
        return resp
    else:
        return jsonify({"status": "error", "message": "登录失败"}), 401

# 方法二：通过 `after_request` 钩子设置 Cookie（适合统一处理）
# 或使用 `session` 对象（更高级封装），但这里先用基础 Cookie 展示原理
Node.js Express 示例

javascript
const express = require('express');
const app = express();
app.use(express.urlencoded({ extended: true }));

    const password = req.body.password;

            secure: false,    // 仅 HTTPS 传输

        res.status(401).json({ status: 'error', message: '登录失败' });
    }
});

参数	作用	示例
key	Cookie 的名称	user_id
value	Cookie 的值	admin

path	哪些路径下发送此 Cookie	/（所有路径）
httpOnly	禁止前端 JavaScript 访问	True（推荐开启）

    'admin': {'name': '管理员 Alice', 'email': 'admin@example.com'},
    'bob': {'name': '普通用户 Bob', 'email': 'bob@example.com'}
}

def login():

    password = request.form.get('password')

        resp = make_response(jsonify({
            "status": "success",
            "message": f"欢迎回来，{USERS[username]['name']}！"
        }))
        # 设置 Cookie，保存用户标识
        resp.set_cookie('user_id', username, max_age=3600, path='/', httponly=True)
        return resp

    if not user_id or user_id not in USERS:
        return "请先登录", 401

    user = USERS[user_id]
    return f"欢迎回来，{user['name']}！邮箱：{user['email']}"

// 如果后端设置了 httpOnly=True，前端将无法访问该 Cookie
为什么需要 HttpOnly 标志？
如果 Cookie 没有设置 HttpOnly，攻击者可以通过跨站脚本（XSS）攻击窃取用户的 Cookie。设置 HttpOnly=True 可以防止 JavaScript 读取 Cookie，从而增强安全性。

3.5.7 Cookie 与 Session 的关系

概念	说明
Cookie	存储在浏览器中，每次请求自动发送，用于保存用户标识（如 user_id）
Session	存储在服务器中，用于保存用户完整的登录状态和数据
两者配合	Cookie 中存一个 session_id，服务器通过这个 ID 在内存或数据库中查找对应的 Session 数据
上面的示例中，我们直接在 Cookie 中存储了 user_id。更安全的做法是：

Cookie 中只存一个随机的 session_id
服务器用这个 session_id 去查询数据库或缓存中对应的用户信息
这样即使 Cookie 被窃取，攻击者也只知道一个随机 ID，无法直接获取用户信息
Flask 内置的 session 对象就是这种机制的封装：

python
from flask import session

app.secret_key = 'your-secret-key'  # 用于加密 Session

@app.route('/login', methods=['POST'])
def login():
    username = request.form.get('username')
    if username == 'admin':
        session['user_id'] = username  # 存储到 Session
        session['user_name'] = '管理员 Alice'
        return "登录成功"
    return "登录失败"

@app.route('/dashboard')
def dashboard():
    user_id = session.get('user_id')  # 从 Session 中读取
    if not user_id:
        return "请先登录"
    return f"欢迎回来，{session.get('user_name')}！"
Flask 的 session 数据默认存储在客户端 Cookie 中（经过加密），所以不需要服务器端存储。适合小规模应用。对于大规模生产环境，建议将 Session 存储在 Redis 等外部缓存中。

3.5.8 本节总结

步骤	说明
1. 用户登录	浏览器发送表单（用户名 + 密码）
2. 后端验证	检查账号密码是否正确
3. 返回 Cookie	验证成功后，在响应中设置 Set-Cookie 头
4. 浏览器保存	浏览器自动保存 Cookie（根据 max_age 过期）
5. 后续请求自动发送	每次请求浏览器自动在请求头中带上 Cookie
6. 后端识别用户	通过 request.cookies 读取 Cookie，识别用户身份
7. 超时或手动退出	Cookie 过期或主动清除后，用户需要重新登录

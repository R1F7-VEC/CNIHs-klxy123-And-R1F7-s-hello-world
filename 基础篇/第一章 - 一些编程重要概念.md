## 1.1 变量：一个给数据命名的标签

可以把它看作一个数据的名字.当然，它指代的数据会变.

举一个例子（伪代码）：

```
name = "Dick"
age = 25
```

在这个例子中，`name` 指的是 `"Dick"` 这个字符串，`age` 指的是 `25` 这个数.

**核心规则**：变量本身不存数据，只指向数据.你执行 `age = 26` 时，只是让 `age` 不再指向 25 而是指向 26.

**解释**：变量名是数据的“标签”，赋值是“贴标签”的动作.

**创造性思考**：如果去掉引号呢？如果变量名不赋值直接使用呢？

**实验**：

```
1. 去掉引号

print(hello world)

触发了 SyntaxError：语法有问题.
实际上，代码必须要符合语法.否则编译器和解释器（都是把你输入的代码转换成机器的 0 和 1 来运行的东西）不知道你在说啥.

2. 变成变量名

print(hello)

报错了：hello 变量没有值.
实际上，单纯的 `hello` 在 Python 解释器看来是变量而不是字符串.但是 hello 没有值，所以出现了报错.

在 Lua 环境里面这么弄，屏幕上会出现“nil”（空的）而没有报错.在有些环境里面，没有定义一个值的变量的值是“nil”.
```

**推理**：所以，`print` 函数会这么做：

```
1. 读取内容
2. 判断它是字符串还是变量
3. 如果是字符串，直接输出
4. 如果是变量，先找它的值，再输出
```

**批判性思维**：不同语言对“未定义变量”的处理方式不同.Python 直接报错，Lua 输出 nil.这说明语言的设计哲学不同——Python 倾向于“早报错早发现”，Lua 倾向于“宽容处理”.没有绝对的对错，只有适用场景的不同.

**命名规则（符合代码风格审查）**：

1. 只包含字母、数字、下划线
2. 不能以数字开头
3. 不能是关键字（比如 `if`、`else`、`for`、`in`）
4. 建议使用下面的命名法：
   - 小驼峰：`thisIsAVar`
   - 大驼峰：`ThisIsAVar`
   - 下划线：`this_is_a_var`

## 1.2 数据类型：值的分类

每个数据都有它的类型，这决定了它可以做到的操作.

| 类型 | 示例 | 说明 |
|------|------|------|
| 整数（int） | `67` | 没有小数部分的数 |
| 浮点数（float） | `3.14159` | 有小数部分的数 |
| 字符串（str） | `"hello world"` | 文本，用引号括起来 |
| 布尔值（bool） | `True / False` | 真的或假的，用于判断是否成立 |
| 列表/数组（list/arr） | `[1, 2, 3]` | 有序的元素集合 |
| 字典/表/对象（dict） | `{"name": "Alice"}` | 键值对 |
| 元组（tuple） | `(1, 2, 3)` | 不可改动的有序集合 |

**核心原则**：数据类型与这个数据可执行的操作挂钩.你不能把一个字符串 `"string"` 当成整数来用.

Python 里面用 `type()` 函数判断数据的类型.

**解释**：类型决定了数据能参与什么运算，能做哪些操作.

**创造性思考**：如果把一个字符串和一个数字相加，会发生什么？如果强行转换类型呢？

**实验**：

```
1. 字符串加数字

print("67" + 67)

报错了：TypeError.
Python 不让你直接把字符串和数字相加.

2. 强行转换

print("67" + str(67))

输出 "6767".
把数字 67 转换成字符串 "67"，然后拼接.

3. 数字加数字

print(67 + 67)

输出 134.
```

**推理**：类型不是“限制”，而是“说明”.它告诉你这个数据能做什么，不能做什么.如果你需要跨类型操作，必须显式转换.

**批判性思维**：有些语言（如 JavaScript）会“自动类型转换”，`"67" + 67` 会输出 `"6767"` 而不是报错.这看起来更方便，但容易产生意想不到的 bug.Python 选择“不自动转换，强制显式操作”，这更安全，但写起来更繁琐.两种设计各有取舍.

## 1.3 列表 / 数组 / 表：有序集合

在讲列表之前，先讲一下数学中的“集合”概念，因为列表和集合有相似之处.

**定义**：集合是由若干确定的、互不相同的元素组成的整体.

集合的性质：

1. **确定性**：集合内元素必须是确定的，范围不能模糊
2. **互异性**：集合里无重复元素
3. **无序性**：集合内元素无顺序

因此，集合与数组的区别是：一个有顺序，一个无顺序.所以集合内没有索引一说.

**描述集合的方法**：

1. **列举法**：列举出集合内所有元素，如 `A = {1, 2, 3}`
2. **图示法**：用一个封闭图形表示集合
3. **描述法**：`S = {x | P(x)}`，其中 `P(x)` 表示 x 具有性质 P

**元素与集合的关系**：属于（∈）、不属于（∉

**集合与集合的关系**：包含于（⊆）、包含（⊇）

**集合的运算**：交集、并集、补集、差集、对称差、笛卡尔积

**列表**用于存储一组有序的数据，可以用索引（位置）来访问其中的元素.

```python
memes_67 = ["67", "61"]
print(memes_67[0])  # 输出 "67"
```

在这个例子中，先造了一个叫 `memes_67` 的表，然后输出那个表内索引是 0 的数据.

> **注意**：除开 Lua 索引从 1 开始以外，大多数语言内数组的索引都从 0 开始.

列表可以修改：

```python
memes_67.append("69")
print(memes_67[2])  # 输出 "69"
```

**解释**：列表是有序的、可变的元素集合.索引是元素的位置编号.

**创造性思考**：如果访问一个不存在的索引呢？如果列表里放不同类型的数据呢？

**实验**：

```
1. 访问越界索引

print(memes_67[99])

报错了：IndexError.
列表没有那么长，你访问了一个不存在的位置.

2. 放不同类型的数据

mixed = [1, "hello", True, 3.14]
print(mixed)

输出 [1, "hello", True, 3.14].
Python 的列表可以放不同类型的数据.

3. 修改元素

memes_67[0] = "6767"
print(memes_67)

输出 ["6767", "61", "69"].
```

**推理**：列表是有序的、可变的、可以存储任意类型数据的容器.索引从 0 开始，越界会报错.

**批判性思维**：有些语言（如 C++ 的数组）要求所有元素类型相同，有些语言（如 Python 的列表）允许混合类型.类型相同的数组在内存中更紧凑，读写更快；混合类型的列表更灵活，但性能稍低.选择哪种取决于你的需求.

## 1.4 条件判断：给程序决定权

条件判断可以让程序在不同情况下做不同的事.

```python
age = 6767

if age >= 18:
    print("你是成年人")
else:
    print("你是小孩")
```

上面的代码中，我们定义变量 `age` 指向数据 6767，然后进行条件判断.如果 `age` 大于等于 18，则输出“你是成年人”，否则输出“你是小孩”.

类似 `if age >= 18` 的式子叫做**条件表达式**，它最终会变成一个布尔值（True 或 False），然后通过这个布尔值来执行哪一个代码.

> **注意**：一般的 if 条件判断部分是从上往下执行，只要找到一个条件成立的，下面就不会走了.这里是一个容易犯错的地方.

**解释**：条件判断根据布尔值决定执行哪段代码.

**创造性思考**：如果多个条件同时成立呢？如果条件永远不成立呢？

**实验**：

```
1. 多个条件同时成立

score = 85

if score >= 60:
    print("及格")
elif score >= 80:
    print("良好")
elif score >= 90:
    print("优秀")

输出 "及格".
因为第一个条件 score >= 60 已经成立，后面的就不再检查了.

2. 条件永远不成立

if False:
    print("这行永远不会执行")
else:
    print("执行 else 分支")

输出 "执行 else 分支".
```

**推理**：if-elif-else 是从上往下依次检查，第一个成立的条件执行后，后面的全部跳过.

**批判性思维**：这个“从上往下，命中即停”的规则，导致条件的顺序很重要.如果你把 `score >= 60` 放在 `score >= 90` 前面，那么优秀的学生也会被判定为“及格”.这不是语言的 bug，而是使用者的逻辑错误.写代码时，必须考虑条件之间的覆盖关系.

## 1.5 循环：重复执行一段代码

循环用于重复执行一个操作，直到满足某个条件为止.

一般有两种循环：

**1. for 循环**：用于遍历一个数组

```python
fruits = ["fruit67", "fruit69"]
for fruit in fruits:
    print(fruit)
```

**2. while 循环**：在条件成立时持续执行

```python
count = 0
while count < 5:
    print(count)
    count = count + 1
```

上面代码中，我们定义变量 `count` 指向数据 0，条件成立（count 小于 5）就一直加，加到 `count = 5` 时条件不成立，停止循环.

**解释**：循环重复执行代码块，直到条件不再满足.

**创造性思考**：如果 while 的条件永远成立呢？如果循环体里忘记改变条件呢？

**实验**：

```
1. 忘记改变条件

count = 0
while count < 5:
    print(count)

程序会无限输出 0，停不下来.
因为 count 永远是 0，条件永远成立.

2. 循环体不执行

count = 10
while count < 5:
    print(count)

什么都不输出.
因为一开始条件就不成立.
```

**推理**：while 循环的关键是“让条件有机会变成 False”.如果你不在循环体里改变条件变量，循环永远不会停止.

**批判性思维**：无限循环不一定是 bug.有些程序故意设计成无限循环（比如服务器的主循环），靠外部信号来终止.关键在于“你是否能控制它”.如果你不知道它什么时候会停，那就是 bug；如果你知道它在等外部信号，那就是特性.

## 1.6 函数：一段打包起来反复利用的代码

编程里的函数就是从数学里的函数继承出来的.

**编程内**：一段打包循环利用的代码.

古人为了偷懒，不想 Ctrl+C 和 Ctrl+V.因此只需要命名并且封装一段代码，就可以循环利用.只需要写它的名字，代入你想要的值，就可以直接调用了.

```python
def greet(name):
    print("Hello, " + name)

greet("69")  # 输出 "Hello, 69"
```

`greet` 是我们定义的函数，`name` 是我们定义的要代入的参数，然后执行了对应操作.

**数学方面：函数是一种映射.**

**映射的基本定义**：

一个映射由三个部分组成：

- **定义域**：输入值的集合（允许输入的范围）
- **值域**：输出值所在的集合（所有可能输出的范围）
- **对应规则**：将每个输入映射到唯一一个输出值的规则

如果定义域为 X，值域为 Y，规则为 f，则可以把映射表示为：

```
f: X → Y
```

如果一个 X 内的元素为 x，代入 x 返回的结果为 y，则有：`f(x) = y`.

**映射的分类**：

| 名称 | 定义 | 含义 |
|------|------|------|
| 单射（Injective / 一对一） | 不同的输入映射到不同的输出 | 不存在两个不同的输入产生相同输出 |
| 满射（Surjective / 映上） | 陪域中的每一个值都至少被一个输入映射到 | 陪域中没有“未被使用”的元素 |
| 双射（Bijective） | 既是单射又是满射 | 每个输入对应唯一输出，每个输出对应唯一输入，存在逆映射 |

**函数是啥**：就是把映射搬到数的范围内.例子：如 `f(x) = x + 61`，则 `f(5) = 67`.

**解释**：函数是输入到输出的映射规则，编程函数封装了一段可重复使用的代码.

**创造性思考**：如果函数没有 `return` 呢？如果传入的参数数量不对呢？

**实验**：

```
1. 没有 return

def greet(name):
    print("Hello, " + name)

result = greet("69")
print(result)

输出 "Hello, 69" 和 "None".
因为函数没有 return，所以返回 None.

2. 参数数量不对

greet()

报错了：TypeError.
函数需要 1 个参数，你给了 0 个.
```

**推理**：函数是一个“映射规则”，它把输入（参数）映射到输出（返回值）.没有 return 时，输出是 None.参数数量必须匹配定义.

**批判性思维**：编程函数和数学函数最大的区别是“副作用”.数学函数 `f(x) = x + 1` 没有任何副作用——它只是计算并返回结果.但编程函数可以打印、可以修改外部变量、可以读写文件.这些“副作用”让编程函数比数学函数更强大，但也更危险.好的编程习惯是：尽量让函数“纯”，减少副作用.

## 1.7 内存模型简述（为后续章节打基础）

当你创建一个变量时，系统会在内存中分配一个位置来存储它的值.这个位置可能是“栈”上的一个临时区域，也可能是“堆”上的一块动态存储空间.

- **基本类型**（数字、布尔值、短字符串）→ 通常存储在**栈**中
- **复杂类型**（列表、对象、表）→ 通常存储在**堆**中，变量只存储指向它们的“引用”

这一章你只需要记住这个区别即可，后续章节会详细解释它如何影响函数参数的行为.

**解释**：内存分为栈和堆，基本类型存栈，复杂类型存堆.

**创造性思考**：如果把一个列表传给函数，函数内部修改它，外面的列表会变吗？如果是数字呢？

**实验**：

```
1. 传列表

def modify(lst):
    lst.append(999)

my_list = [1, 2, 3]
modify(my_list)
print(my_list)

输出 [1, 2, 3, 999].
外面的列表变了.

2. 传数字

def modify_num(n):
    n = n + 1

my_num = 5
modify_num(my_num)
print(my_num)

输出 5.
外面的数字没变.
```

**推理**：列表是引用类型——传给函数的是“地址”，函数内部修改的是同一块内存.数字是值类型——传给函数的是“副本”，函数内部修改的是副本，不影响原来的.

**批判性思维**：这个区别导致很多初学者写出“修改列表成功但修改数字失败”的 bug.理解这个区别，你就能预测函数的行为，而不是靠试错.

## 1.8 模块与库：代码的复用与组织

你已经理解了函数可以把一段代码“打包”起来重复使用.当你的程序逐渐变大时，你可能想把多个相关的函数放在一起，形成一个更大的结构——这就是模块和库的用途.

**模块（Module）**：一个包含代码的文件.

模块是一个包含函数、变量、类等定义的文件.你可以把它看作一个“工具箱”，里面存放着多个相关的工具.

Python 示例：

假设你创建了一个文件 `math_utils.py`：

```python
# math_utils.py 是一个模块

def add(a, b):
    return a + b

def multiply(a, b):
    return a * b

PI = 3.14159
```

然后你在另一个文件中导入并使用这个模块：

```python
# main.py
import math_utils

print(math_utils.add(3, 5))       # 输出 8
print(math_utils.multiply(2, 4))  # 输出 8
print(math_utils.PI)              # 输出 3.14159
```

这样，你就在不同的文件之间复用了代码.

**解释**：模块是代码的组织单位，让你把相关功能放在一起，方便复用.

**创造性思考**：如果两个模块有同名的函数呢？如果模块名和变量名冲突呢？

**实验**：

```
1. 两个模块同名函数

# module_a.py
def greet():
    print("Hello from A")

# module_b.py
def greet():
    print("Hello from B")

# main.py
import module_a
import module_b

module_a.greet()  # 输出 "Hello from A"
module_b.greet()  # 输出 "Hello from B"

不冲突，因为调用时必须带模块名前缀.
```

**推理**：模块通过“命名空间”隔离了不同文件中的同名函数.你用 `module_a.greet()` 和 `module_b.greet()` 来区分它们.

**批判性思维**：模块化是大型项目的基础.没有模块化，所有代码堆在一个文件里，很快就会变得无法维护.但模块化也引入了新的问题：依赖管理、版本冲突、循环导入.这些是工程问题，不是语言问题.语言只是提供了工具，怎么用好是程序员的责任.
